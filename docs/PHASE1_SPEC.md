# 股流 Radar｜Phase 1 PWA 核心產品規格與 Wireframe（修正版）

**版本：** v0.2  
**產品定位：** 台股熱門類別探索＋價格行為交易研判  
**核心價值：** 先找出資金與價格聚焦的熱區，再用價格行為框架判斷「可以觀察什麼、等待什麼、何時不交易」。  
**產品原則：** 提供條件式交易情境與風險規劃，不保證獲利，不把統計訊號包裝成明牌。

---

## 1. 修正後的 Phase 1 目標

Phase 1 不再只是「看法人資金流向」，而是驗證以下完整流程：

```text
市場掃描
  ↓
找到熱門類別／熱區
  ↓
選擇類別或個股
  ↓
查看價格行為圖表
  ↓
由研判模組產生條件式交易情境
  ↓
使用者自行判斷是否等待、觀察或執行
```

### Phase 1 必須完成

- 手機優先 PWA，可加入手機主畫面。
- 今日熱門類別排行與熱度分層。
- 類別熱度來源可解釋：資金、漲跌、成交量、廣度等。
- 熱區內個股列表與排序。
- 個股價格圖表，至少支援一個主要時間框架。
- 價格行為研判分析卡，固定採用使用者指定的六段框架。
- 清楚區分「已確認資訊」「推測情境」「尚需等待條件」。
- 進場區域、結構失效位、止損、止盈與預期盈虧比的條件式規劃。
- 單一時間框架限制提示。
- 自選熱區／個股暫存於 Local Storage。
- 顯示資料日期、更新狀態、資料來源與分析時間。

### Phase 1 暫不完成

- 自動下單或券商串接。
- 無使用者確認的自動交易。
- 直接宣告「買進」「賣出」或「一定上漲」。
- 完整多時間框架自動判讀；先保留介面與資料結構。
- LINE Messaging API 推播；Phase 2 再接。
- 個人化風險承受度與完整投資組合管理。
- 歷史勝率或獲利保證。

## 2. 產品角色與使用者任務

### 產品角色

股流 Radar 不是單純排行工具，而是兩段式產品：

1. **雷達：** 找出市場中值得進一步研究的熱門類別與個股。
2. **研判：** 對使用者選定的圖表，按照價格行為框架拆解結構、關鍵位、形態、交易情境與風險。

### 使用者任務

| 任務 | 產品回應 |
|---|---|
| 哪些類別正在變熱？ | 熱門類別排行、熱度分數與熱度來源 |
| 熱區內有哪些股票？ | 類別成分股、資金與價格排序 |
| 這檔股票現在的結構如何？ | 市場結構與多空級別摘要 |
| 可以怎麼規劃？ | 順勢做多、順勢做空、等待確認、不交易情境 |
| 哪裡算錯？ | 結構失效位與條件失效說明 |
| 風險有多大？ | 進場區域、止損、止盈、R 倍數與倉位公式 |

## 3. 熱門類別定義

「熱門」不可只用單日漲幅定義，Phase 1 應拆成可解釋的熱度訊號：

```text
類別熱度 =
  資金流向 35%
+ 價格強度 25%
+ 成交量異常 20%
+ 上漲廣度 20%
```

這是產品內部的排序分數，不代表預測報酬率，也不代表買賣建議。

### 熱區分層

| 分層 | 意義 | 使用者下一步 |
|---|---|---|
| 聚焦 | 資金、價格、廣度同步偏強 | 進入類別查看圖表與候選股 |
| 升溫 | 資金或價格開始改善，但尚未完全同步 | 觀察突破或回踩確認 |
| 分歧 | 資金與價格方向不一致 | 降低解讀信心，等待條件 |
| 退潮 | 資金與價格同步轉弱 | 避免追價，尋找結構重新建立 |

### 熱區頁必須顯示

- 熱度分數與分層。
- 今日／近 5 日／近 20 日變化。
- 資金流入或流出。
- 類別上漲家數／下跌家數。
- 成交量相對近期平均的變化。
- 主要貢獻個股。
- 「熱門不等於可交易」提醒。

## 4. 價格行為研判框架

所有個股分析都使用同一份結構化輸出，不讓模型只給一句模糊結論。

### 4.1 判斷市場結構

輸出：

- 大級別：上升、下降或震盪。
- 小級別：上升、下降或震盪。
- 高點與低點：HH、HL、LH、LL 或不明確。
- 大小級別是否一致。
- 結構信心：高、中、低。

### 4.2 識別關鍵價位

輸出：

- 支撐區。
- 壓力區。
- 突破位。
- 回踩區域。
- 結構失效位。
- 每個價位的依據與資料範圍。

價位應顯示為區域而非過度精確的單一價格，避免製造虛假精準度。

### 4.3 分析價格行為

檢查並標示：

- Pin Bar。
- 多空吞沒。
- 雙頂／雙底。
- 突破與假突破。
- 回踩確認。
- 信號 K 線。
- 入場 K 線。

沒有足夠證據時，顯示「未確認」，不可強行辨識形態。

### 4.4 提出交易情境

至少提供其中適用的情境：

- 順勢做多：需要哪些確認？
- 順勢做空：需要哪些確認？
- 等待確認：等待什麼價位、K 線或結構變化？
- 不交易條件：例如區間中間、盈虧比不足、訊號互相矛盾、資料不足。

交易情境不是直接下單指令，應使用「若……則……」的條件式語句。

### 4.5 制定風險管理

輸出：

- 進場區域。
- 止損位置與結構依據。
- 第一止盈與第二止盈。
- 預期盈虧比。
- 單筆風險金額。
- 倉位計算公式。
- 移動止損方案。

倉位公式：

```text
可承受風險金額 = 帳戶淨值 × 單筆風險百分比
每股風險 = 進場價格 − 止損價格（做多）
建議股數 = 可承受風險金額 ÷ 每股風險
```

實際下單股數仍需考慮整股／零股、流動性、跳空、滑價、交易成本與市場規則。

### 4.6 明確區分三種資訊

畫面固定使用三個區塊：

1. **已確認的圖表資訊**：只列圖表與資料直接支持的內容。
2. **推測情境**：依結構與價格行為推導的可能路徑。
3. **尚需等待的條件**：尚未發生，不能當成已確認訊號。

若只有一個時間框架：

> 本分析僅根據目前選定的單一時間框架，無法確認更大級別趨勢是否一致；請勿將此結果視為完整多時間框架分析。

## 6. 主要使用流程

### 流程 A：從熱門類別找到候選股

```text
熱區
  ↓
查看聚焦／升溫類別
  ↓
查看熱度來源與類別廣度
  ↓
進入類別詳情
  ↓
選擇候選個股
  ↓
開啟價格行為研判
```

### 流程 B：研判分析

```text
選擇股票
  ↓
選擇時間框架
  ↓
閱讀市場結構
  ↓
確認支撐、壓力、突破與失效位
  ↓
查看價格行為形態
  ↓
查看多空／等待／不交易情境
  ↓
設定自己的風險參數
```

### 流程 C：避免追高

```text
熱門類別
  ↓
價格已遠離支撐或接近壓力
  ↓
研判標示「等待回踩／不追價」
  ↓
列出回踩確認條件
```

熱門類別只負責「發現」，不自動推導「應該買進」。

### 7.4 分析結果的固定區塊

每個研判結果必須依序顯示：

```text
已確認的圖表資訊
推測情境
尚需等待的條件
風險與失效位
分析限制
```

不要把「推測情境」放在「已確認資訊」之前，避免使用者把預測誤讀為事實。

## 8. 建議與風險邊界

產品可以提供：

- 教學式價格行為解釋。
- 條件式多空情境。
- 等待條件。
- 結構失效位。
- 風險報酬估算。
- 倉位計算工具。

產品不可提供：

- 保證獲利或勝率。
- 無條件的買賣指令。
- 根據熱門程度直接推薦股票。
- 在單一時間框架下宣稱完整趨勢判斷。
- 因價格上漲很多就直接判定即將反轉。
- 把歷史回測當成未來結果保證。

### 建議產品文案

> 熱區用來縮小研究範圍；價格行為用來規劃條件；風險管理用來決定能否承受。任何情境都必須等條件成立，且由使用者自行判斷。

## 9. Phase 1 API 與資料模型

### 熱區

```text
GET /api/hotzones?range=today
GET /api/hotzones/:id
GET /api/hotzones/:id/stocks
```

### 圖表與研判分析

```text
GET /api/stocks/:symbol/chart?timeframe=1w
POST /api/pa/analyze
```

分析請求至少包含：

```ts
interface CoachAnalyzeRequest {
  symbol: string;
  timeframe: "1w" | "1d" | "60m" | "15m";
  candles: Candle[];
  marketContext?: MarketContext;
  riskProfile?: {
    accountSize?: number;
    riskPercent?: number;
  };
}
```

分析回應應結構化：

```ts
interface CoachAnalysis {
  confirmed: string[];
  scenarios: Scenario[];
  waitingConditions: string[];
  structure: StructureAnalysis;
  keyLevels: KeyLevel[];
  patterns: PatternFinding[];
  riskPlan?: RiskPlan;
  limitations: string[];
  disclaimer: string;
}
```

`POST /api/pa/analyze` 在 Phase 1 可以先使用規則引擎與固定模板；若日後加入 LLM，LLM 只能協助解釋與整理，不應取代價位計算、資料驗證與風險限制。

## 10. 開發順序修正

### Sprint 1：熱區探索

- 建立 PWA 專案與品牌 UI。
- 建立熱度資料模型。
- 完成熱區首頁、分類篩選、類別詳情。
- 先用 mock data 驗證「使用者能否找到熱門類別」。

### Sprint 2：候選股與圖表

- 類別內個股列表。
- 個股搜尋。

### Sprint 3：價格行為研判

- 固定六段分析輸出。

- 交易情境卡與風險計算器。
- 空資料、資料不足、衝突訊號狀態。

### Sprint 4：PWA 與測試

- manifest、service worker、安裝提示。
- 375px、390px、768px 響應式檢查。
- 圖表與列表數值一致性測試。
- 價格行為分析結果的人工案例驗證。
- 確認不會把推測語句顯示成已確認資訊。

## 11. Phase 2 預留：LINE 策略推播

Phase 2 將「熱門類別」與「你的交易策略」串接：

```text
熱門類別出現
  ↓
篩選類別內股票
  ↓
套用價格行為策略條件
  ↓
條件未完成：記錄等待狀態
  ↓
條件完成：建立候選訊號
  ↓
風控與去重
  ↓
LINE Messaging API 推播
```

LINE 訊息應使用「策略條件已符合」而不是「現在買進」，並附上：

- 股票與類別。
- 使用時間框架。
- 已確認條件。
- 尚未確認條件。
- 結構失效位。
- 風險提示。
- 開啟完整分析頁連結。
